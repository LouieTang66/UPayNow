## 为什么选择 UPayNow？

### 不必把签名私钥放上服务器

与需要服务器持有热钱包、自动签名的方案不同，UPayNow 的合约部署和资金归集由你的外部钱包确认。服务器负责订单与付款识别，不负责保管签名私钥。

### 一单一地址，支付更省心

每笔订单拥有独立收款地址，无需用户回填交易哈希，也无需通过带特殊尾数的金额区分订单。用户按订单金额转账，系统自动识别到账，让支付流程更简单。

### 资金归集到哪里，由合约固定

已部署合约的归集目标不可更换，也不能在调用归集时临时指定其他地址。资金去向不只是后台配置中的一个可修改字段。

### 为自己的生意收款，不必运营一个支付平台

一个商户后台管理多条受支持的 EVM 链，通过 API 接入现有商城。无需先搭建多商户注册、分账和结算体系。

## 收款流程

1. **商城创建订单**  
   商城通过 API 创建收款订单，UPayNow 返回独立收款地址和支付页面。

2. **用户完成付款**  
   用户按支付页面指定的网络、币种和金额转账，无需回填交易哈希。

3. **系统确认并通知**  
   UPayNow 检测链上付款，核验金额并等待所需确认数，再向商城发送带签名的付款通知。商城验证通知后完成发货或交付。

4. **商户按需归集**  
   商户可选择单笔或批量归集，由自己的钱包确认交易并支付 Gas，将资金转入合约固定的收款钱包。

```text
商城创建订单 → 用户付款 → 链上确认 → 通知商城 → 发货或交付
                            │
                      资金留在订单地址
                            ↓
                    商户按需确认归集
                            ↓
                      固定收款钱包
```

付款确认与资金归集相互独立，商城无需等待归集完成即可处理已确认的订单。

## 快速开始

### 1. 安装并启动

准备 Node.js 22.19 或更新的兼容版本及 npm，获取源码后，在项目根目录运行：

```bash
npm ci
npm start
```

默认管理入口为 `http://127.0.0.1:8790`。首次启动后，使用实例生成的恢复密钥设置管理密码，之后通过密码登录。

### 2. 配置收款网络

在“链与合约”中点击“添加链”，选择已开放网络；系统自动填写 RPC、Chain ID 和 Gas 币符号，无需手动填写。再填写自己的固定收款钱包、准确代币合约地址，并核对付款确认数。自定义 RPC 仅在高级设置中按需使用。

使用固定收款钱包确认商户合约部署并支付该链 Gas；公共入口由维护方准备，商户无需另行部署。也可以导入经过核验、与当前版本兼容的已有合约。

### 3. 接入商城

使用独立 API 凭据创建收款订单，将用户引导至支付页面，并配置付款通知地址。商城验证通知签名后完成发货或交付。

### 4. 验证首笔收款

建议先在测试网走通创建订单、付款、通知和归集流程，再接入正式业务。

生产部署前，请先按[安装与 HTTPS 部署](docs/INSTALLATION.md)配置持久数据目录及访问入口。逐步操作见[商户操作手册](docs/OPERATIONS.md)，密码设置与恢复方式见[认证说明](docs/AUTHENTICATION.md)，商城对接见[API 文档](backend/README.md)。其他技术文档见[文档索引](docs/README.md)。

## 安全与备份

### 钱包私钥由你保管

UPayNow 不需要上传钱包私钥或助记词。合约部署和资金归集通过你自己的钱包确认，请妥善保管钱包及其备份。

### 管理凭据与钱包私钥分开

管理密码用于登录后台，恢复密钥用于首次设密或重置密码，独立 API 凭据用于商城接入。请勿将这些凭据放入顾客网页、公开仓库或截图。

### 备份完整实例数据

请定期对完整数据目录和运行配置进行一致性备份，包含认证文件、各链部署记录、订单及任务数据，并将备份保存在服务器之外。

恢复密钥不能替代业务数据备份；也不要直接复制正在写入的单个数据库文件作为完整备份。

### 保护服务器与支付页面

服务器不保存钱包私钥，并不意味着可以忽略服务器安全。请配置 HTTPS、限制管理入口访问，并保护支付页面，防止收款地址被篡改。

详细部署要求与安全边界见[安全说明](docs/SECURITY.md)。
