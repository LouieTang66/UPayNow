# 跨链确定性部署（v2）

**简体中文** | [English](CROSSCHAIN-V2.md)

所有新建商户部署均采用本方案；它不会升级现有链上合约。旧版 CREATE 部署仍支持历史导入和找回，保留原订单哈希、付款记账和不可更改的归集去向，但不能新建旧版部署。升级应用不会让已有地址自动具备找回能力。商户操作请见[商户操作手册](OPERATIONS.md)；本文说明部署与找回的技术边界。

## 地址构造

原有负责转移资金的 `ForwarderFactory` 和 `ForwarderImpl` 合约保持不变。新的 `DeterministicDeployer` 通过 CREATE3 模式创建商户 Factory：

1. 使用规范的 ERC-2470 SingletonFactory 和固定 salt 部署版本锁定、无构造函数的确定性部署器。
2. 部署器使用与方案版本和商户收款地址（payout）绑定的 salt，创建代码固定的 CREATE2 代理。
3. 代理使用其第一次 CREATE 部署未改动的商户 Factory，并传入该链核准的代币列表。
4. Factory 按原方式创建实现合约，并根据原订单哈希和 payout 预测每笔订单对应的克隆合约地址。

在支持且兼容的链上，采用相同的已验证公共部署入口地址、编译产物、版本、payout 和原订单哈希，可复现相同的 Factory、实现合约及订单地址。商户交易的 nonce 和各链单独的代币列表不决定这些 CREATE3 Factory 地址。每条链的代币白名单仍在构造时固定；CREATE3 使链特定的构造参数不参与跨链 Factory 地址的确定。

必须锁定合约版本和字节码。用不同设置重新构建，或更改部署器、其中内嵌的 Factory 创建代码，都可能改变该方案的公共根合约地址。不要把任意新构建产物宣称为兼容已发出的 v2 地址。

## 信任与授权

规范 SingletonFactory 地址为 `0xce0042B868300000d44A59004Da54A005ffdcf9f`。其运行时字节码必须与已公布的 ERC-2470 部署完全一致，仅占据预期地址并不够。官方原始部署交易哈希为 `0x803351deb6d745e91545a6a3e1c0ea3e9a6a02a1a4193b70edfcd2f40f71a01c`（依赖复制值前，先对照官方 ERC 核实）。

如果规范 Factory 不存在或为仿冒合约，部署 API 必须拒绝操作。不得在用户的真实网络上静默为规范部署者账户注资或广播其原始交易。验证通过的规范 Factory 是链的前置条件，并不意味着任意 EVM RPC 都受支持。

初始化无构造函数的公共根合约不需要许可。创建商户 Factory 时，交易发送者必须等于不可更改的 payout，防止他人用商户不想要的代币列表占用其确定性地址。抢跑者、代理调用者或找回操作者都不能更改此固定收款地址。不能发出相应钱包交易的 payout（例如交易所充值地址）不适合 v2 部署模式。旧版部署不因此新增该限制。

复用已有 Factory 时，会验证完整身份与严格按原顺序排列的代币登记表。列表不同（包括仅调整条目顺序）即为冲突，不代表可以修改构造时固定的白名单。在 v2 方案中，每组 payout、链与锁定的部署器版本仅对应一个商户 Factory；不能通过改变核准代币列表，用同一个 payout 部署第二个同版本 Factory。请保留旧部署。不同 payout 会构成不同部署身份；不同合约系列或版本的兼容性需要另行评审，不能通过当前界面强制覆盖。也不能靠新建旧版部署绕开限制。创建代理会拒绝创建它的确定性部署器之外的调用者。创建失败时，代理的创建及其已使用标志均会回滚。

## 应用流程

商户在界面选择已开放网络后，界面会填入默认 RPC、Chain ID 和原生 gas 币符号。高级 HTTPS RPC 覆盖设置不会开放其他网络，也不会跳过代码核验。新建任务仅接受 deterministic-v2（省略方案也创建 v2）；legacy-v1 仅用于历史导入和找回。可通过 `GET /api/deployment-networks` 查看后端开放网络列表。

网络运营方通过[独立公共部署工具](../ops-public-deployer/README.md)预部署并验证公共根合约。即使携带管理员 Bearer 凭据，普通后端也会拒绝新建公共初始化任务，返回 403 `PUBLIC_BOOTSTRAP_OPS_ONLY`。历史初始化任务仍可走原恢复路径。商户无需先发一笔交易初始化根合约；公共代码不存在或无效时，商户部署会被阻止。开放政策与链上及代码的实时核验是两个独立条件；提供任意 RPC 或由运营方成功初始化，并不意味着该网络已向商户开放。

确定性部署的调用有 `to` 地址：运营方初始化调用已验证的 SingletonFactory；商户创建调用已验证的确定性根合约，要求 `from == payout`，且钱包在该链上有 gas。已有旧版创建交易不含 `to`。钱包意图校验会区分两种情形，而不是关闭接收方校验。仍需严格验证网络、发送者、金额（value）、calldata、交易目标以及回执和区块。UNKNOWN 不等于失败，不会触发自动重发。专用手机部署流程在尚无已知哈希时，可在原截止时间前，针对同一个已批准任务和身份显式地再次弹出钱包请求；这受到限制，也不能证明原请求未曾广播。

商户创建支持桌面注入钱包、桌面 WalletConnect 或专用手机能力链接。WalletConnect 需要商户自己的 Reown Project ID，可在尚未部署时保存；专用手机入口不需要它。固定 HTTPS 手机入口不依赖 cloudflared。临时入口按需准备版本锁定且通过校验和验证的官方组件，普通启动不会打开该入口；详见[组件说明](../backend/CLOUDFLARED.md)。

公共根合约初始化成功不等于商户部署成功，不得因此登记空 Factory。商户部署成功后，必须核验预期事件、运行时字节码、不可更改的 payout、实现合约及其代码哈希、白名单和足够的确认数，才能登记部署。

## 错链找回

请保留原订单哈希，不要用新的随机 UUID 创建替代账单。生成找回预览需要两个 Chain ID 不同且分别登记的 deterministic-v2 部署；系统会重新验证两条链上的规范代码与不可更改字段，核对 payout、Factory、部署器和实现合约是否一致，并验证两条链的预测地址均等于原订单地址。仅有公共根合约准备就绪不够，目标链上的商户部署也必须已登记并通过验证。预览查询的是显式选择的目标链合约地址（CA；原生资产使用零地址），不会把代币符号或 RPC 标签当作身份证明。

找回任务是持久化且限定在目标链上的归集任务，不是新账单。不得修改来源订单的已支付状态、发出支付成功 webhook、静默自动接受另一种资产或凭空生成跨链桥接。资金归集到目标链上的固定 payout，之后由商户决定如何退款或记账。

专用找回必须由目标部署的 payout 钱包签名，并在目标链准备 gas。支持桌面注入钱包和桌面 WalletConnect，不支持专用手机交接流程。这条更严格的发送者规则不适用于普通同链的无许可归集，其 gas 支付者不必是 payout。若找回结果未知，进入目标部署的归集恢复视图核对原交易，不要另起一次尝试。外部钱包归集任务若明确拒签，仍会继续观察 64 个区块；管理员手工处理会将任务标记为 ABANDONED 并结束自动观察，不等于经过链上核验或确认付款。

在整个钱包审批期间，找回界面必须锁定目标部署和原订单身份。切换钱包网络或部署选项不得改变交易去向。没有哈希仍属于需要核对的未知结果，并不意味着可以安全重发。

## 验收要求

使用两个独立的本地 EVM 链，采用不同的 Chain ID、不同的商户交易 nonce 和不同的获准代币 CA。用同一个锁定版本的确定性部署器进行初始化，验证 Factory、实现合约以及订单地址均相同，在目标链的预计算地址尚无代码时转入真实的测试代币，再执行部署并将其找回到固定 payout。

还应覆盖：未经授权的配置和创建、代理访问、重复部署、复用时的代币列表不匹配、不支持或仿冒的公共初始化代码、取消及未知交易结果的持久化、链和作用范围变更、来源付款及 webhook 不被改变，以及所有旧版合约和后端的回归测试。

在本地测试夹具中写入规范字节码，不能证明真实链上已有这段字节码。请明确测试夹具的适用范围，在将网络列为受支持前另行核验真实链前置条件。本地测试不授权任何真实网络部署或转账操作。

## 限制

找回需要兼容且受支持的链和可转移的资产。冻结、恶意代币行为或签名钱包不可用都可能导致失败。地址文本相同，并不能证明商户控制另一条链上以不同方式部署的合约钱包。payout 若不是普通外部账户（EOA），必须确认商户在目标链上的控制权。

现有 Factory 不可升级。请完整保留其记录与地址算法。改用新方案是为之后的新部署和新订单作出的选择，不会改写旧订单或旧余额。
