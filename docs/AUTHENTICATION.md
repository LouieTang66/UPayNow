# 密码、恢复密钥与 API 凭据

三种凭据各自独立：

- 密码：日常登录后台、修改密码、验证后查看凭据。
- 恢复密钥：首次设密或忘记密码时重置，不能直接登录或调用业务 API。
- API 凭据：仅供商城服务器调用业务接口，不能管理密码或查看凭据。当前仍有广泛业务管理权限，不得放入顾客网页或公开仓库。

初次部署见 [安装说明](INSTALLATION.md)，日常设置、备份与异常恢复见 [完整操作手册](OPERATIONS.md)，商城接入见 [服务器 API](../backend/README.md)。

## 首次设置

服务为实例随机生成恢复密钥与独立 API 凭据，保存在数据目录的 `auth.json`。首次设密需要恢复密钥证明身份，不能由任意首访者抢先设置。

部署者可在项目根目录明确取回，数据目录使用 `UPAY_DATA_DIR` 或命令参数：

```sh
npm run recovery-key -- /实际数据根目录
# macOS/Windows 直接复制到剪贴板，不显示明文：
npm run recovery-key -- --copy /实际数据根目录
```

工具只读取本机文件，不改密码、不创建凭据。不要把明文输出发到聊天或日志。

打开管理入口，设置并确认自己的密码（12–128 个字符，保留空格、不能全为空白），保存界面生成的新恢复密钥，再使用密码登录。首次设密通过 `POST /api/auth/reset` 完成，也会轮换恢复密钥；首次取回的旧 key 此后失效。密码不能直接使用恢复密钥或 API 凭据。

## 修改与重置

在设置中修改密码需要当前密码；忘记密码则在登录页输入恢复密钥与新密码。两者都会注销全部会话；修改密码保留原恢复密钥，重置会换新恢复密钥，必须保存。API 凭据不受改密或重置影响。

恢复密钥和 API 凭据可在设置中再次验证密码后查看、复制或下载；关闭后清除界面值。重置响应丢失时，可尝试新密码登录后取回恢复密钥，或由部署者使用上述本机工具。不要删除认证文件来绕过验证。

当前密码重认证输错返回 401 `UNAUTHORIZED`，不撤销仍有效的当前会话，可在原弹窗更正；401 `SESSION_REQUIRED` 则需要重新登录。登录、设密/重置、改密和凭据查看共享按连接地址计数的认证限流：5 分钟窗口内最多 10 次，超限为 429 `AUTH_RATE_LIMIT`（不是旧前端词典中的 `LOGIN_RATE_LIMIT`）。成功请求也计数，不要持续重试；并发繁忙可返回 503 `AUTH_BUSY`。

## 存储

`auth.json` 保存加盐 scrypt 密码记录和两种密钥，不存明文密码；文件权限为 0600，修改以原子替换保存。认证文件损坏时拒绝启动，不自动重建。

会话使用 HttpOnly、SameSite=Strict Cookie，HTTPS 下启用 Secure，8 小时有效，重启后重新登录。保留同源、Host、限流和并发校验；浏览器不将密码或密钥写入 URL、localStorage 或 sessionStorage。

备份须包含认证文件、数据库、部署及任务状态，并按敏感数据保护。
