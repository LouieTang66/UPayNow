# 开发与隔离检查

**简体中文** | [English](DEVELOPMENT.en.md)

本文面向维护者，不是商户安装/付款步骤；首次使用请看[安装说明](INSTALLATION.md)和[商户操作手册](OPERATIONS.md)。命令以当前根 `package.json` 为准。

## 运行前

- 使用支持 `node:sqlite` 的 Node.js 22.19 或更新的兼容版本及锁文件安装依赖。
- 使用独立、一次性的测试目录和本地测试链，确认命令不会读取商户真实数据目录或访问生产服务。
- 不在真实 state 中运行测试/清理，不自动连接钱包、使用私钥、广播公网交易或开启公网隧道。
- 源码、编译输入、manifest、ABI 与已部署字节码要分别核对；测试输出不能代替生产验收。

## 应用构建与定向测试

```sh
npm ci
npm run build
npm run test:backend
npm run test:frontend-v2
```

`npm run build` 包括合约输入校验/编译和前端构建，不是仅构建文档。`test:backend` 会先自动执行 `pretest:backend`（编译与前端构建），前端测试没有同样的预构建钩子，先执行构建再测。上述命令会安装依赖或写构建产物；阅读文档不表示这些命令已执行。小范围修改优先运行对应测试文件，不为一处文案改动反复运行全套测试。

根 `npm test`、`npm run test:crosschain`、`npm run test:compat` 也是开发检查入口，各自的覆盖和隔离前提以实际脚本为准；不保证任何一次运行天然全绿。浏览器脚本入口见[前端开发说明](../frontend-v2/README.md)。

## 确定性合约与跨链测试

具体隔离场景和命令见[本地跨链合约验收说明](../test/fixtures/CROSSCHAIN.md)。`npm run build:input` 会重建导出源码输入；不要把重建输入作为绕过编译校验、修改 Solidity 首行或更新固定 manifest 的快捷方式。

当前发布绑定的 compiler/settings、salt、源码输入、规范字节码和地址必须保持一致。未经新版本设计和独立验证，不更新这些发布输入或产物，也不因构建成功就认为旧地址可原地升级。

分叉测试可能访问外部 RPC，真实公网/手机检查可能创建外部资源或产生交易请求，均不属于普通离线测试默认步骤。先核实目标、凭据、数据目录与相应授权，不因文档列出脚本就自动执行。

## 检查结果的表述

写明实际执行的命令、覆盖、返回结果及未执行项。代码静态核对、内存链测试、浏览器测试、实体钱包、生产 HTTPS 和真实网络到账是不同证据，不能互相替代。

文档整理的静态检查与应用构建应分别记录结果。
