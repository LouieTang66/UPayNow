# UPayNow 安装与部署

**简体中文** | [English](INSTALLATION.en.md)

仓库：<https://github.com/LouieTang66/UPayNow>。通过已获授权的访问方式获取源码，进入项目根目录。以下从全新空白实例开始，不需要复制任何现成链配置或个人部署数据。

本文面向部署者；后台逐屏操作见[商户操作手册](OPERATIONS.md)，文档总入口见[文档索引](README.md)。

## 1. 环境和运行目录

使用 Node.js 22.19 或更新的兼容版本（需要 `node:sqlite`）、npm，以及能够持久化 SQLite 并正常实施文件权限的本地文件系统。Node 某些版本会对 SQLite 提示 experimental 警告；安装成功不是数据库生产认证。

以独立服务账户运行。在首次启动前，将 `UPAY_DATA_DIR` 设置为部署者选择的受保护持久目录。变量值应为实际绝对路径，不要使用临时目录、公开静态目录、缺乏权限保护的移动介质，或与其他实例共用目录。未设置时默认使用项目相对目录 `backend/state/`。

服务读取**进程环境变量**；仓库的 `.env.example` 只是无真实数据的配置说明，不会被自动加载。请通过进程管理器、容器环境或 shell 显式注入。商户 Factory、payout、CA 和订单通过认证后的产品流程配置，不在环境样例中预置。程序内置已开放网络及 RPC 预设，选择网络后自动填写网络参数；这不等于预置商户合约或订单。

## 2. 安装启动与首次设密

在项目根目录执行：

```sh
npm ci && npm start
```

首次启动不配置任何网络、不部署 Factory、不创建订单。默认仅监听本机 `127.0.0.1`。打开 `http://127.0.0.1:8790`，以部署者恢复密钥确认身份后设置密码；日常仅使用密码登录。恢复密钥的只读取回工具及重置流程见[认证说明](AUTHENTICATION.md)，启动日志不会打印任何凭据。

密码、恢复密钥和商城 API 凭据分离；恢复密钥仅用于设密/重置，不能登录或充当 Bearer。商城使用独立 API 凭据，仍有广泛业务管理权限，并非最小权限开单 token。运行目录 `auth.json` 是敏感认证状态，不能放入聊天、截图、工单、公开目录或 Git。不要删除认证文件冒充恢复或轮换。

根目录与每套部署的状态包括 SQLite、通知密钥和任务记录；新部署子目录位于 `deployments/<uuid>/`。每套部署有自己的 `webhook.secret`，商城验签端应安全取得其对应密钥，而不是一律使用根目录密钥。通知密钥不应交给浏览器。

## 3. 三个专用 HTTPS 入口

对外使用前，由部署者提供 DNS、受信任 TLS 证书和反向代理。三个角色应使用独立 origin；下列均为保留示例域名，不是可用服务：

| 环境变量及示例 | 默认本机上游 | 角色 |
|---|---|---|
| `UPAY_PUBLIC_ORIGIN=https://merchant.example.com` | `http://127.0.0.1:8790` | 管理台、商城 API、顾客收银台 |
| `UPAY_HANDOFF_ORIGIN=https://collect.example.com` | `http://127.0.0.1:8791` | 手机本次归集页及受限接口 |
| `UPAY_DEPLOYMENT_ORIGIN=https://deploy.example.com` | `http://127.0.0.1:8792` | 手机本次 Factory 部署页及受限接口 |

端口可由 `UPAY_PORT`、`UPAY_HANDOFF_PORT`、`UPAY_DEPLOYMENT_PORT` 调整。origin 使用纯 HTTPS origin，不加路径、query、fragment 或用户名密码。代理应保留配置的 Host；浏览器写请求的 Origin 必须与对应入口一致，不通过放开 CORS 或伪造来源绕过校验。

不要把手机域名转发到管理端口，或将管理凭据放入手机二维码。管理服务同时提供顾客收银台和 API：如限制管理面网络访问，应由部署者精确划分代理路径和访问策略，保留所需收银台/API，并自行验证；不存在第四个内建管理隔离服务。`/health` 仅表示进程存活及是否配置，不代表链扫描或支付核验健康。

固定 HTTPS 入口不需要 cloudflared。不配置固定手机 origin 时，服务在用户创建手机入口时按需准备 Cloudflare Quick Tunnel：优先检查显式配置的可执行文件，再复用系统可用程序；都未配置或不存在可用系统程序时，在受支持平台从 Cloudflare 官方固定版本发行源自动下载并校验 SHA-256，保存到受保护的数据目录组件缓存。普通用户默认无需提前手工安装。显式指定的 `UPAY_CLOUDFLARED` 路径无效时会报错，不静默换用其他程序；校验失败不执行。具体平台、固定版本和错误见[组件说明](../backend/CLOUDFLARED.md)。

普通服务启动不下载组件、不自动开放公网通道。组件准备和通道连接成功后，临时手机会话最长 5 分钟；入口到期不取消已签名的交易。临时隧道没有持久可用性承诺，第三方平台可能接触流量。生产部署可配置固定入口并自行核查访问边界。不要把 `127.0.0.1` 二维码当作手机可访问地址。

## 4. 添加自己的链和 Factory

登录后进入“链与合约”→“添加链”，从已开放网络名单选择网络。程序自动填写 RPC、Chain ID 和 Gas 原生币符号，新建时后两项只读；默认不需要手填 RPC。只有确需替换节点时，才使用“高级：自定义 RPC（HTTPS）”。商户填写自己的固定 payout、准确且逐链核实的代币 CA，并核对付款确认数。没有预置或推荐收款地址。校验参数与预览不会发交易。

- **新部署**：仅在已开放且公共入口就绪的网络创建 deterministic-v2 商户部署。公共入口由项目运营方准备，不是普通商户必须再签的一笔交易。连接电脑钱包、WalletConnect 或受限手机部署入口，核对网络、payout、CA 后明确确认。签名账户必须等于固定 payout，并支付该链 Gas。服务核验原部署调用、确认数、规范字节码及不可变字段后，才登记 Factory。
- **导入**：填写自己的兼容 Factory 和正确扫描起始区块，完成链上身份核验；导入本身不付部署 gas。不能仅凭合约名字/ABI 相似就视为兼容。

当前新建商户部署由 payout 账户调用已存在的固定公共入口，交易具有 `to`，不是要求商户从账户直接广播无接收地址的合约创建交易。服务还保留历史 legacy 部署任务的核验与已有合约导入；这不代表开放新建 legacy 模式。任意智能账户或交易所充值地址不保证具备所需签名能力。目标链需支持当前合约使用的 EIP-1153/Cancun 等指令；仅同为 EVM 或 RPC 可用并不足以证明兼容。原生 Gas 币显示按 18 decimals 处理，不适用于任意非 EVM 链。

payout 和支持 CA 部署后不可改。同链、同 payout、同部署版本的 Factory 地址固定，不能仅改币种列表就重新部署一套；需要不同配置时，须规划独立部署，例如使用另一个由自己控制的固定收款钱包，并保留旧部署及历史订单。钱包连接、二维码打开、RPC 可用均不表示部署成功。超时或断线保持 UNKNOWN，查找钱包原哈希并登记恢复，不能盲目重新部署。精确按钮和恢复步骤见[商户手册第2章](OPERATIONS.md#2-添加网络与部署收款合约)。

## 5. 商城接入和归集

先设置准确的 `UPAY_WEBHOOK_HOSTS` 域名白名单，并在商城服务器保存独立 API 凭据、部署 ID 和相应通知密钥；见 [商城接入](../backend/README.md)。订单由商城 API 创建；顾客仅接触随机付款链接，不持有管理凭据。

付款与归集是两套状态。商城验证签名、去重并查单后幂等履约；商户查看归集预览，由自己的钱包确认并支付 gas。异常、重组、迟付、错币都不能直接等同付款成功。

## 6. 停止、备份和恢复

使用进程管理器正常停止或发送 SIGTERM/SIGINT。不得同时运行两个实例占用同一状态目录。异常退出后可能遗留 `owner.lock`；先确认对应进程已结束，再由部署者处理遗留锁，不能删除正在运行实例的锁。

备份、监控、更新、证书续期及恢复演练由部署者负责。备份范围是**完整状态根目录及所有部署子目录**，包括配置、密钥、订单、通知与未知任务；使用一致的 SQLite 备份机制，或正常停止后完整备份。热复制单个 `merchant.sqlite` 不保证 WAL 数据完整。备份亦含敏感凭据，应加密并限制访问。

恢复时保留密钥和原交易记录，核查链上状态后再处理 UNKNOWN。不要清库掩盖问题，不要将旧订单重新指向新 Factory。升级前保留可恢复备份；应用升级不会升级链上不可变合约。其余限制见 [安全说明](SECURITY.md)。
