# UPayNow 安全限制与部署者核查

**简体中文** | [English](SECURITY.en.md)

部署准备见 [安装说明](INSTALLATION.md)，日常管理、备份与未知交易恢复见 [完整操作手册](OPERATIONS.md)。

## 当前产品边界

- 单商户、单进程、SQLite 状态持久化；同一目录只能一个实例。不是多租户、多角色、高可用或内建容灾平台。后台使用密码会话；恢复密钥只负责设密/重置；独立 API 凭据仍有广泛业务管理权限，但不能访问密码管理或凭据查看接口。不是最小权限开单 token，无多角色、MFA或API轮换界面。详见[认证说明](AUTHENTICATION.md)。
- 主管理服务同时提供收银台/API；手机部署和归集是两个专用受限服务，不提供管理登录或管理列表。部署者必须正确映射三个 HTTPS origin、保护管理访问，不能以开放 CORS、禁用 TLS 校验或转发手机域名到管理端口来解决访问问题。
- RPC、数据库、通知密钥、完整能力链接均属敏感数据。RPC URL 可能在路径/query 中含服务商凭据；禁止放到截图、日志、公开文档或二维码。应将其视为服务端秘密，即使页面未展示也要核查 API 返回边界。
- 服务端不因钱包已连接就持有其私钥。标准启动使用外部钱包逐笔确认部署/归集并付 gas，不应配置或上传商户钱包私钥。
- Quick Tunnel 是可选第三方临时访问通道，无稳定性承诺，平台可能接触流量。固定 HTTPS 的证书、DNS、访问控制和运维由部署者提供。

## 合约不可变性与资产限制

- payout 和支持 CA 名单构造后不可修改，无管理员、升级、暂停、Hold、收费或改向接口。增币、换钱包、改版本需新 Factory，不能改旧订单。钱包失陷或发行方限制可能持续影响旧订单，没有管理员救援。
- 每个 Factory 仅作用于所在链；相同 CA 在不同链也不是同一配置。基本代码存在检查和 decimals 不证明资产真实或兼容，不能只看 name/symbol。
- 当前合约使用 transient storage guard，需要目标链实际支持 EIP-1153 等指令；不承诺所有 EVM 链均适配。编译设置为 Solidity 0.8.38、optimizer 200、viaIR、Cancun；链兼容性需独立核查。
- 正常归集读取一次转前余额并使用 SafeERC20，不核验商户净增量或转后清零；不支持转账税、rebasing、伪造余额/转账语义的代币。`Collected.amount` 是请求转出量，不是净到账承诺。
- 所有支持 CA 都不能走错币入口；错币/原生币处理只会转到固定 payout，不是退款。不要向 Factory 或 implementation 付款：它们没有余额找回入口。只向对应订单地址支付准确币种。
- 任何人可以付 gas 调用归集，但不能选择其他收款人。二维码到期只能撤回网页发起能力，不能撤销已下载 calldata、已广播交易或合约本身的 permissionless 权限。
- 批量拒绝空数组，但无固定数量、单项 gas cap 或全批 gas 保留保证。极端耗 gas 可使后续项受影响甚至全批回滚。应预演、留余量、合理拆批，按 `(订单,CA)` 逐项核对；成功尝试数不等于付足订单数。
- 固定 payout 不防御收银台/服务失陷后显示攻击者地址；必须保护发布产物、管理权限和业务订单映射。

## 付款与通知

只认可准确代币的有效链上付款记录，不能用当前余额、归集事件或交易外层 status 替代。支持有限深度的重组处理；超出保存锚点范围需要人工重建历史。确认数不是协议 finalized，RPC 错误或扫描未追平时不得假装已健康核验。

通知是可重试网络投递，不是 exactly-once。商城应使用订单所属部署的 `webhook.secret`（不是一律根目录密钥），对 `timestamp + "." + 原始正文` 校验 HMAC 与时间窗；`X-Upaynow-Event` 是事件 ID，不是类型。按事件 ID 去重、按 stateVersion 拒绝陈旧覆盖，并实现订单级幂等履约与 payment.reversed 对账。自动投递最多 8 次，手动重新排队保留事件 ID；通知 2xx 仅表示可靠接收，不证明商城履约或归集成功。UPayNow 不管理库存、发货或退款。商户接受迟付只接受特定已确认到账快照，不绕过库存决策或重组处理；当前只有管理认证 API，没有 UI 接受按钮。详见 [通知与迟付 API](../backend/README.md)。

## 钱包与未知结果

先持久化发送意图，再交付钱包；UNKNOWN 表示可能已发送。断线、刷新、隧道关闭、超时或没有收到哈希均不证明未广播，不应自动重发。明确拒签登记也不是链上未广播证明。应保存任务 ID，先登记原钱包哈希并核对真实链状态；钱包任务人工 `resolve` 会解除任务锁定并停止该任务自动观察，记录的人工结果不是链上成功证明、不撤销交易。

钱包部署目前面向普通 EVM 账户直接发送交易。新建只开放名单网络的 deterministic-v2 商户部署，由固定 payout 钱包调用经核验的确定性部署入口，钱包请求含 `to`；公共入口预部署属于运营方操作，不是商户添加链流程。历史 legacy-v1 可核验导入，不是当前新建入口。选择内置网络自动填写 RPC，不免除链与代码核验。不承诺全部智能账户/账户抽象部署方式。注入钱包、WalletConnect、手机内置浏览器以及 EIP-681 扫码的兼容性均需部署者用自己的设备与目标网络确认。

普通归集允许其他钱包付 Gas，收款人仍固定；专用错链找回要求目标链 payout 钱包签名并在目标链付 Gas。当前没有钱包分组或跨链归集队列，必须按链/部署核对任务。

## 跨链确定性部署与找回

- 新模式必须核验目标链的 canonical ERC-2470 运行代码，以及当前固定版本部署器的运行代码。目标地址有代码不等于代码正确；缺失公共入口的链不能仅凭 RPC 可用就标为支持。
- 商户 Factory 通过 CREATE3 重现，链上 token 白名单仍固定；只有固定 payout 钱包可以初始化对应商户 Factory，防止别人抢先锁定错误配置。交易所充值地址等不能主动发送部署交易的 payout 不适用于此模式。公共部署器本身没有管理员、收费或改向接口。
- 同地址要求相同部署器版本、payout 和原订单哈希。升级构建、改代码或重新生成订单都可能改变地址；不能重写旧 Factory、旧订单或假称它们自动具备新恢复能力。
- 找回必须绑定原订单及另一个已核验部署域，在目标链读取指定 CA/原生币余额并逐笔确认交易。任务与源链付款识别、统计、通知隔离；找回不代表源链付款成功，也不是桥接或自动退款。
- 找回能力不能绕过代币冻结、转出限制、链指令不兼容或目标链收款钱包不受商户控制。智能合约钱包在另一链具有相同文字地址，也不证明相同控制权。归集事件金额仍不代表商户净到账。
- 恢复任务持久化且参与目标部署的并发互斥、未知哈希核对及重组检查。切换链/当前部署不得改变已经批准的任务范围；未知结果不得通过重新建任务绕过。

设计与本地验收要求见 [跨链同地址部署与恢复](CROSSCHAIN-V2.zh-CN.md)。

## 上线前需复核的恢复与隐私边界

以下项目需要按所安装的具体版本和实际部署复核，不能仅凭正常启动或自动化测试通过就认定所有异常窗口均已覆盖：

- **候选交易哈希恢复**：部署任务登记候选哈希后，更正错误哈希的路径和限制需要确认。不得通过清库或重复部署绕过未知结果。
- **手机 RPC 隐私**：需检查手机接口是否返回含凭据的完整 RPC URL；页面不展示不等于服务端不再下发。
- **部署范围一致性**：header/query/body 的 deploymentId 冲突处理需要统一核查。集成方应只使用一种范围来源；开单 header/body 保持一致。
- **异常退出恢复**：owner.lock、数据库一致性及 UNKNOWN 恢复需专项确认；正常重启不等于所有崩溃窗口均安全。

未经专项复核，不将这些边界定性为当前版本全部存在问题或全部解决。公开部署前应将未确认项纳入风险决策。
